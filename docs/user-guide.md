# 用户指南

## 基本概念

- 文档 A / 文档 B：一次对齐的两份自然文档，不预设谁更权威。
- 关系：两侧若干内容块的直接对应，可为 1:1、N:1、1:M、N:M 或单侧缺失。
- 工作报告：保存对齐、修订、AI 与审核状态的 JSON 文件。
- 固化修改：把选定类型的报告操作写入文档，并重建剩余工作状态。

## 推荐流程

1. 打开两份文档并运行对齐。
2. 检查低分、非 1:1 和单侧缺失关系。
3. 进行人工校订，按需调用 AI 审校并逐条确认建议。
4. 使用“保存工作报告”保存进度；自动保存也只更新报告。
5. 若希望 Markdown 接纳部分校订，先在“文件 → 固化范围”选择类型，再执行“固化修改”，审阅两侧差异后确认。

固化范围包含文档 A/B 各自的合并、拆分和文本校订，以及同时删除两侧内容的“删除文本对”。占位用于工作状态表达，不作为正文固化类型。常用预设：

- “仅校订文本”：只写入人工或 AI 的正文替换，不改变段落结构；
- “行级兼容（全部）”：同时固化合并、拆分、校订与文本对删除，使可以固化的关系直接反映到两份文档；
- “仅文档 A / B”：只改变指定一侧，另一侧的修改继续留在报告中。

部分固化后，已写入的效果从当前修复记录消失，未写入的效果会重锚到新快照。同时改变两侧结构的 N:M 合并/拆分必须同时启用 A/B 对应类型，否则整体保留。`flag` / `ok` 不会写入正文：关系仍存在时继续留在当前报告；删除使关系消失时则保存在固化历史中。自动或 AI 正文修改及删除仍需人工确认后才能固化。

“文档操作”中的“对齐策略”控制自动校订如何处理多对一关系：可以优先减少正文修改，也可以分别以文档 A 或文档 B 的段落结构为基准。它不是文件导出格式；切换策略本身不会写入正文，只有执行自动校订后才会更新工作报告。

关闭并重新打开同一对文档时，只要正文哈希未变化，程序可从报告恢复状态。若正文被外部修改，旧报告会被拒绝，需重新对齐。

## 阅读器输出

Dualign 不再维护 `repaired/` 目录。阅读器构建过程会临时重放报告并生成等行文本，完成后删除临时文件。无需在 GUI 中手动导出。

## 数据安全

“保存”不会碰源文件。“固化修改”会修改源文件且不额外生成 `.bak`；需要长期版本历史时，请把正文和报告纳入 Git 或其他备份系统。
